# 直したものを次に活かす

> [Traccia](../README.md) のドキュメント。版の残し方・差分の見方・作法の学習について。

---

自動の文字起こしは、精度がどれだけ上がっても最後は人が直すことになる。
**その「直した結果」は、次の文字起こしを良くする材料になる。**

そのために Traccia は 3 つのことをする。

1. 性質のちがう版を**別々に残す**
2. 版どうしの差を**種類ごとに分けて見せる**
3. 差から測れる「この現場の作法」を**次の文字起こしに渡す**

---

## 1. 残っている版

編集しているのは `<名前>.edit.json` で、これは今までどおり。それとは別に、
性質のちがう版が固定の名前で残る。

| ファイル | 中身 | 書かれるとき |
|---|---|---|
| `<名前>.edit.json` | いま編集しているもの | 4 秒ごとの自動保存 |
| `<名前>.auto.edit.json` | **文字起こしの生出力** | 文字起こしを流した瞬間。毎回上書き |
| `<名前>.manual.edit.json` | **人が直し切った確定版** | wfp を取り込む直前に 1 回だけ |
| `<名前>.wfp.edit.json` | **Filmora から取り戻した最終版** | wfp を取り込むごとに上書き |

「話者設定」を開くと **「残っている版」** の欄に一覧が出る。

### なぜ生出力を別に残すのか

文字起こしを流した直後の `edit.json` は機械の出力そのものだが、**編集を始めると
4 秒ごとの自動保存で上書きされ、`backup/` の 5 世代からも 20 秒ほどで押し出される。**
あとで「機械はどこを間違えたか」を見ようにも、比べる相手が残っていない。

### 手作業版が守られる仕組み

wfp を取り込むと `edit.json` は丸ごと差し替わる。何時間もかけて直した結果が
入っていることがあるので、その前に `manual.edit.json` へ退避する。

退避するのは**次の両方を満たすときだけ**。

- `manual.edit.json` がまだ無い
- いまの `edit.json` が wfp 由来ではない

つまり **2 回目以降の wfp 取り込みでは退避しない。** 2 回目の時点で `edit.json` は
1 回目の抽出結果なので、それで手作業版を上書きしたら意味がない。結果として
**「手作業版 1 つ + wfp 版 1 つ」が常に並ぶ。**

やり直したいときは、「話者設定」の **「いまの状態を手作業の確定版にする」** で
置き直せる。上書きされた版も `backup/` に残る。

## 2. 差分を見る

上の **「差分を見る」** で別タブが開く。読むだけの画面なので、編集の状態には触らない。

左（比べる側）と右（正とする側）を選ぶ。いちばん中身があるのは
**「文字起こしの生出力 ↔ 手作業の確定版」**。

### 分類

| 種類 | 何 | 学習に使う |
|---|---|---|
| 一致 | そのまま使えた | — |
| 時刻 | 本文は同じで、置いた位置がちがう | ○ |
| 話者 | 話者の割り当てがちがう | ○ |
| 表記ゆれ | かな / 漢字・送り仮名のちがい | ○ |
| 語の誤り | 語が 1〜2 か所ちがう | ○ |
| 区切り | 1 行の分け方がちがう | ○ |
| 句読点 | 句読点・記号だけの差 | **×（演出）** |
| 削り | 相槌・言い直しを削った | **×（演出）** |
| 書き換え | 大きく違う。機械では判定できない | **×（要判断）** |
| 欠落 / 余剰 | 片方にしか無い | ○ |

**句読点を落とした・相槌を削ったのは演出上の書き直し**であって、文字起こしの誤りでは
ない。混ぜて学習させると、文字起こしの出力が最初からテロップ寄りになる。だから
既定で学習から外している。

### 全体のずれ

Filmora で頭を詰めると、wfp から取った版は全体が前へ寄る。実測では **−26.6 秒**
ずれていて、そのままだと 709 行すべてが「時刻がちがう」になり、本当に見たい差が
埋もれた。

そこで**全体のずれは 1 回だけ上に報告して、表では差し引いた残りを出す。**
これで一致が 2% → 55% になった。

### 音で確かめる

行をクリックすると、**その位置の 4 秒前後だけ**音が鳴る。境目を判断したいときに
頭が切れると分からないので、少し前から鳴らしている。

## 3. 作法を学ぶ

差分の画面の下に **「この差分から分かること」** が出る。

### なぜ効くのか

文字起こしのプロンプトは長らく「1 区間は 1〜5 秒程度」と指示していた。ところが
**実際に人が作る字幕は中央 1.43 秒**だった。指示が実態と合っていない。

実測に合わせて流し直した結果（29 分の素材・確定版 734 行を正解として）:

| | 行数 | 総字数 | 1 行の尺 | 拾えた行 | 欠落 |
|---|---|---|---|---|---|
| これまで | 570 | 7,953 | 2.20s | 67% | 350 |
| **実測に合わせた** | 913 | 8,041 | 1.50s | **75%** | **174** |
| 確定版（人） | 734 | 7,833 | 1.43s | — | — |

総字数はほぼ変わらない。**内容が増えたのではなく、同じ内容を細かく割っただけ。**
時刻の精度は動かない（そちらはローカル文字起こしとの併用で解いている）。

### 1 つの固定値では足りない

手元の確定版 5 本を測ると、素材ごとに **0.7 秒の幅**がある。

```
bluebottle 1.27s 9字 / ooseyana 1.26s 9字 / spring_valley 1.44s 10字
yellow_company 1.43s 10字 / princi 1.94s 12字
```

だから**セットごとに測る**。確定版が無いセットは同じ場所の他セットの中央値、
それも無ければ既定値（1.5 秒前後・10 文字前後）に落ちる。

**機械の出力からは測らない。** 今の癖をそのまま学び直すことになるので、
`origin` が `transcribe` の `edit.json` は材料にしない。

### 承認するまで変わらない

測っただけの値は使わない。素材が変われば作法も変わるし、**黙って変わると、
なぜ出力が変わったのかが分からなくなる。**

提案にはチェックを入れて「反映」を押す。根拠は必ず数字で出る
（「確定版 734 行から測定」）。**1 つ前に戻す**もあり、初回の反映でも戻せる。

反映した内容は `<名前>.style.json` に残る。

### 語の学習は、期待したほど効かなかった

「いつも間違える語を辞書に足す」という案もあったが、実データでは材料が集まらなかった。

```
語の誤り 145 件 → 語として取り出せた 44 種 → 固有名詞らしいもの 2 種
そのうち 2 回以上繰り返されたもの: 0 種
```

**1 本の素材では、同じ誤りが繰り返されない。** 素材をまたいで数えるようにしたが、
それでも候補は数種で、表記ゆれが中心だった。

いまは候補として出すだけにしてある。効く範囲が狭いことを承知のうえで使うもので、
**この仕組みの中心は作法の反映のほう。**

## 文字起こしの出力について

**目印は付かない。** 目印は行頭の番号をクリックして自分で付けるもの。機械が
付けたものが混ざると、自分で付けた印が埋もれる。

**同じ話者どうしの重なりも無い。** 同じ人が同時に二言喋ることはないので、
出す時点で詰めてある（実測では 470 件中 83 件が重なっていた）。
別の話者との重なりは残るので、同時発話かどうかは見て判断する。

## ファイルの置き場所

```
<セット>/
  <名前>.edit.json           いま編集しているもの
  <名前>.auto.edit.json      文字起こしの生出力
  <名前>.manual.edit.json    人が直し切った確定版
  <名前>.wfp.edit.json       wfp から取り戻した最終版
  <名前>.style.json          反映した作法（履歴つき）
  <名前>.feedback.json       差分の結果（比較画面が書く）
  backup/                    上書き前の 5 世代
```

どれも素材フォルダの中に置かれる。**原本の `.srt` には一切書き戻さない。**
